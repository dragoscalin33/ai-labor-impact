# Deploying the project

The canonical public surface is the Next.js site on Vercel. Streamlit,
Docker and local Python are kept as alternative entry points for reviewers
who want to inspect or run the engine without the frontend.

| Path                          | Use for                                          | Time   | Cost |
|-------------------------------|--------------------------------------------------|--------|------|
| **Vercel (Next.js site)**     | Public link to share on LinkedIn / CV            | 5 min  | Free |
| **Streamlit Community Cloud** | Interactive Python dashboard on the same engine  | 5 min  | Free |
| **Docker**                    | Reviewers who want full local control            | 1 min  | Free |
| **Local Python / npm**        | You, while iterating                             | <1 min | Free |

---

## A) Vercel  *(canonical — what the LinkedIn post points at)*

The site lives under `web/` and is auto-detected as a Next.js 16 app.

### One-time setup

1. **Push to GitHub** (the repo is already public):
   ```bash
   git push origin main
   ```
2. **Link the project**:
   ```bash
   cd web
   npx vercel link --yes --project ai-labor-impact
   ```
   Root directory is auto-resolved to `web/`. No `vercel.json` needed.
3. **Set environment variables** (Project → Settings → Environment Variables).
   All are optional:
   - `GROQ_API_KEY` — enables `/api/insights` to stream live LLM commentary
     instead of serving the cached `web/public/data/insights.json`. The route
     returns `501 { reason: "no_key" }` when the variable is absent and the
     client falls back to cached.
   - `NEXT_PUBLIC_SITE_URL` — canonical URL, used by the sitemap, robots.txt
     and OG metadata. Defaults to `https://ai-labor-impact.vercel.app`.
4. **First deploy**:
   ```bash
   npx vercel --prod --yes
   ```
   Subsequent pushes to `main` redeploy automatically.

### Refreshing the data

The site reads from six JSON artefacts under `web/public/data/`. They are
regenerated by:

```bash
make web-artifacts        # → python3 scripts/precompute_web_artifacts.py
```

Commit + push and Vercel rebuilds. The Python engine is not required at
runtime, only at this build-step.

## B) Streamlit Community Cloud  *(legacy interactive dashboard)*

Useful as a hands-on inspector of the same model, especially for the Monte
Carlo slider and live LLM Insights tab. Not what the LinkedIn post points
at — that is the Vercel site.

1. Sign in at <https://share.streamlit.io> with your GitHub account.
2. Click **New app** and fill in:
   - **Repository**: `dragoscalin33/ai-labor-impact`
   - **Branch**: `main`
   - **Main file path**: `app/dashboard.py`
   - **Python version**: 3.11 (under *Advanced settings*)
3. Click **Deploy**. First build takes ~3–5 min.
4. (Optional) **Secrets**:
   ```toml
   GROQ_API_KEY = "gsk_..."
   ```
   Same fallback rule as Vercel: `data/insights_cache.json` is the no-key
   default.

> **Why the lean `requirements.txt`?** The Cloud install times out after
> ~10 min. The default file omits PyMC, MLflow and Jupyter so cold deploys
> finish in under 5 min. Bayesian and tracking notebooks remain runnable
> locally via `pip install -r requirements-dev.txt`.

## C) Docker

```bash
docker build -t ai-labor-impact .
docker run --rm -p 8501:8501 ai-labor-impact
# → open http://localhost:8501
```

Or with `docker-compose`:

```bash
docker compose up --build
```

The image contains the lean Python runtime and the Streamlit dashboard —
suitable for demoing on a reviewer's laptop without polluting their Python
env. It does not contain the Next.js site (run that separately under `web/`).

---

## D) Local Python and Next.js

```bash
git clone https://github.com/dragoscalin33/ai-labor-impact.git
cd ai-labor-impact
pip install -r requirements.txt

# regenerate site data from the model
python scripts/precompute_web_artifacts.py

# A) Streamlit dashboard
streamlit run app/dashboard.py            # http://localhost:8501

# B) Next.js site (in another shell)
cd web && npm install && npm run dev      # http://localhost:3000
```

For the Bayesian and MLflow notebooks add:

```bash
pip install -r requirements-dev.txt
jupyter lab notebooks/
mlflow ui                                 # http://localhost:5000
```
